## 8. 排序维度

后续每个 P2/P3 问题按以下维度排序：

| 维度 | 判断方式 |
| --- | --- |
| 用户影响 | 是否影响真实家庭愿意继续录入和邀请 |
| 核心闭环关联 | 是否影响建堂、录入、认领、补充记忆、二次补充亲属 |
| 技术风险 | 是否可能破坏已稳定页面 |
| 数据风险 | 是否触碰数据库、RLS、schema、migration |
| 回滚成本 | 是否可以小步回滚 |
| 产品边界 | 是否保持家族关系和记忆资产方向 |

## 9. 当前建议优先级

### P2-1：中文亲属称谓真实人工填写

理由：

- 自动检测已经通过。
- 真实家庭语境仍未填写。
- 称谓是信任问题，不宜只靠机器判断。
- 不需要改代码，可先完成校对记录。

### P2-2：`/family/output` 家堂档案后续性能观察

理由：

- 已做一轮优化。
- 仍是历史观察项。
- 对用户查看“家族记忆整理结果”的体验影响直接。
- 后续可继续做局部优化，不必新增功能。

### P2-3：添加亲属与邀请认领文案复核

理由：

- 直接影响核心裂变闭环。
- 主要是理解成本问题。
- 可以先通过文案和说明优化，不触碰数据库。

### P2-4：2D 图谱移动端操作提示

理由：

- 图谱是产品价值展示面。
- 移动端手势和筛选可能需要更明确提示。
- 不应改算法，只做体验说明验证。

### P3：数据看板解释性、日历文案、空状态细节

理由：

- 不阻断核心闭环。
- 可积累真实反馈后统一处理。
