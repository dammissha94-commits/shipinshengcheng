# 第四阶段 C：中文亲属称谓人工校对样本集

## 1. 阶段名称

第四阶段 C：中文亲属称谓人工校对样本集

## 2. 阶段目标

在不修改代码、不修改数据库、不新增 migration、不调整 RLS 的前提下，建立一套可用于真实家庭测试的中文亲属称谓人工校对样本。

本阶段重点验证：

- 家人档案页称谓是否符合真实家庭理解。
- 成员列表称谓是否自然、准确、不过度推断。
- 三代谱称谓是否清楚。
- 2D 家族关系图标签是否友好。
- 数据不足时 fallback 是否稳妥。
- 称谓表达是否符合中国家庭语境，避免祭祀化、宗教化、纪念馆化。

## 3. 产品边界

吾家祠堂是：

- 家族关系操作系统。
- 私密数字家堂。
- 家族记忆资产库。

吾家祠堂不是：

- 祭祀 App。
- 宗教平台。
- 纪念馆。
- 开放社区。
- IM 聊天工具。
- 支付或募捐平台。

## 4. 校对原则

| 原则 | 说明 |
| --- | --- |
| 宁可保守，不强行推断 | 数据不足时显示“家人”“兄弟姐妹”“祖辈”“孙辈”等保守称谓 |
| 优先符合真实家庭口语 | 避免过度书面、冰冷或不常用的称谓 |
| 不破坏原始关系数据 | 校对只针对展示称谓，不改变 `person_relations` 原值 |
| 不显示技术来源 | 不向用户显示 `KinshipResult.source` |
| 不因称谓失败影响页面 | 称谓计算失败必须保留 fallback |
| 避免祭祀化表达 | 不使用祭奠、供奉、上香、功德、法事等方向 |

## 13. 异常与 fallback 样本

| 编号 | 场景 | 预期结果 | 风险 |
| --- | --- | --- | --- |
| F-001 | 关系类型为空或未知 | 显示原有 fallback 文案 | 不应白屏 |
| F-002 | 性别为空 | 显示保守称谓 | 不应强推断 |
| F-003 | 对方档案缺失 | 显示“家人”或原有文案 | 不应报错 |
| F-004 | kinship adapter 抛错 | 页面继续渲染原有 label | 不应影响主流程 |
| F-005 | 2D 图谱关系筛选 | 筛选结果不变 | 不应因显示文案改变筛选 |
| F-006 | PNG 导出 | 导出逻辑不变 | 不应改导出算法 |

## 14. 暂不校对的复杂关系

当前阶段暂不进入以下复杂关系推断：

- 堂兄弟姐妹。
- 表兄弟姐妹。
- 伯父、叔父、姑姑。
- 舅舅、姨妈。
- 岳父、岳母。
- 公公、婆婆。
- 侄子、侄女。
- 外甥、外甥女。
- 多婚姻、多家庭结构。
- 收养、继亲、半血缘关系。

原因：

- 当前数据模型以低风险三代关系展示为主。
- 数据不足时复杂称谓容易误伤用户信任。
- 后续如需扩展，应先建立关系字段、性别、年龄、父系/母系方向等更完整样本。

## 16. 问题等级

| 等级 | 定义 |
| --- | --- |
| P0 | 称谓展示导致页面白屏、构建失败、核心关系页面不可用 |
| P1 | 称谓明显错误，影响真实家庭理解或信任 |
| P2 | 称谓可理解但不够自然，需要文案优化 |
| P3 | 后续可增强的复杂关系、地区差异或口语偏好 |

## 17. 验收标准

- 家人档案页称谓显示稳定。
- 成员列表页称谓显示稳定。
- 三代谱称谓显示稳定。
- 2D 图谱标签、筛选、图例显示稳定。
- sibling_of 无性别时显示“兄弟姐妹”。
- grandparent_of 无性别时显示“祖辈”。
- 祖辈视角下孙辈无性别时显示“孙辈”。
- 不显示 `KinshipResult.source`。
- 不修改关系原值。
- 不影响图谱布局、搜索、高亮、筛选、PNG 导出。
- 不引入祭祀化、宗教化、开放社区、IM、支付方向。

## 18. 下一步建议

1. 用真实家庭数据执行本样本集。
2. 收集 P1/P2 称谓反馈。
3. 优先修复明显影响理解的 P1。
4. 暂不扩展复杂亲属链，等样本足够后再评估。
5. 若后续接入更多称谓场景，仍必须通过 `src/lib/kinship/kinship-adapter.ts`。
